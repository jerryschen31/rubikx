# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Rubikx is an iOS app for playing with a digital Rubik's cube. The user turns a layer by pushing a sticker on any visible face, rotates the whole cube by dragging off it, and can long-press to grip a layer, as one hand holds a real cube while the other turns it. Each finger turns its own layer, so several fingers can turn parallel layers at once. What matters most is how it feels: animations and gestures should be smooth and natural, and as close to handling a physical Rubik's cube as possible. Use that as the tiebreaker for design decisions. For example, a turn should follow the finger continuously and should not jump in fixed 90° steps. When the user lets go, the layer should settle with momentum and snap to the nearest quarter turn. Gestures should not get stuck or feel laggy.

Rendering uses **RealityKit**. Do not introduce SceneKit, SpriteKit, or a custom Metal renderer.

## Commands

The pure logic lives in the `RubikxCore` Swift package and builds and tests without Xcode (Command Line Tools are enough). Its tests use Swift Testing (`import Testing`), not XCTest, because XCTest isn't available without Xcode.

- Test everything: `swift test --package-path Packages/RubikxCore`
- One suite: `swift test --package-path Packages/RubikxCore --filter FaceDragTests`
- One test: `swift test --package-path Packages/RubikxCore --filter FaceDragTests/frontFacePushesTurnRowsAndColumns`

The app needs full Xcode. The Xcode project is generated by XcodeGen from `project.yml`; `Rubikx.xcodeproj` is gitignored, so run `xcodegen generate` after cloning and after adding or removing files.

- Build: `xcodegen generate && xcodebuild -project Rubikx.xcodeproj -scheme Rubikx -destination 'platform=iOS Simulator,name=iPhone 17' build`
- Test through Xcode (runs the RubikxCore tests): `xcodebuild -project Rubikx.xcodeproj -scheme Rubikx -destination 'platform=iOS Simulator,name=iPhone 17' test`
- Debug builds accept the `-scrambleOnLaunch` launch argument, which plays a scramble so you can see turn animations in the simulator without touch input.
- The simulator can't produce independent multi-finger touches, so multi-finger turns have to be tested on a device.

## Architecture

`Packages/RubikxCore` has no UIKit or RealityKit dependency:
- **Coordinates:** cube-local, with +x right, +y up and +z toward the viewer. Cubie centers are on the integer grid {-1, 0, 1}³. Angles and `Move.quarterTurns` follow the right-hand rule about the positive axis. `Move(notation:)` maps standard notation (R, M, r, x, …) onto this.
- **`CubeState`:** 26 `Cubie`s, each a home position plus an `IntMatrix3` orientation. Every move rotates about the cube's center, so position is always `orientation * home`. `isSolved` checks that each face is a single color, so it ignores whole-cube orientation.
- **`CubeHit` / `FaceDrag`:** `CubeHit` intersects a camera ray with the cube (surface at ±1.5) to find the touched face and point. `FaceDrag` reads a screen drag as movement across that face, using the screen steps per cube unit along the face's two axes, so it works for any face, orientation and perspective. Once the movement has a clear direction it returns a `Grip`: the layer that carries the touched sticker that way, turned about normal × direction. A `Grip` returns the layer's continuous angle, with the touched sticker keeping pace with the finger (one cube unit of drag is 1/1.5 radian).
- **`CubeProjection` / `holdTurn`:** turns made while a long-press grips a layer. `CubeProjection` is an affine view of the cube on screen (screen step per unit along each axis, plus the direction toward the camera). `grippedLayer` says what a long-press grips; `holdTurn` picks the parallel layer a finger's drag turns, by where the finger lies along the grip axis (its hit point on the cube, or its screen offset projected onto the axis off it), and maps the drag along `rimTangent`: how the rim of those layers that faces the camera moves on screen.
- **`LayerSpring`:** the release settle. `snapTarget` projects the release velocity forward to pick the quarter turn, and a damped spring carries the momentum into it.
- **`OrientationSpring`:** the whole-cube equivalent of `LayerSpring`. `CubeOrientation` lists the 24 square-on orientations, and `snapTarget` projects the release spin forward to pick one.
- **`Scrambler`:** random face-turn sequences with no redundant moves.

## Gestures

| Where the finger starts | Drag | Result |
|---|---|---|
| On a sticker of the front, top or right face | across the face | the layer that carries that sticker in that direction (any of the 9 layers, including B, S and E) |
| Off the cube | any | whole cube, trackball |
| Off the cube, two fingers | twist | whole cube about the view axis |
| Anywhere, held still for 0.35s | — | **grips** a layer (haptic plus highlight) until the finger lifts |

What a long-press grips: on an edge sticker, the outer layer along that edge (front left-middle → L); on a center sticker, that face (front center → F); off the cube, the side of the screen it's on (left/right/above/below → L/R/U/D). Every finger already down and still grips with it.

While gripping, only layers parallel to the grip turn, as on a real cube:
- Another finger, on or off the cube, turns the parallel layer it lies in along the grip axis, never the gripped one; past the cube counts as the outer layer. Holding L, a pan on or beside the right side turns R, in the middle M. Holding F, a pan at or beyond the back edges turns B, on the top face's middle row S.
- The drag must run along the layers' rim (the rim facing the camera); drags across it are ignored.
- A gripping finger that drags turns the gripped layer; a second gripping finger turns the next layer in.

Always:
- A finger's layer and direction lock after about 8pt of movement and never change mid-gesture. Unclear directions wait for more movement.
- Layers on the same axis can turn at the same time, one per finger. A turn on a crossing axis waits until every layer is back on the grid, as on a real cube.
- A finger can catch a layer that is still settling.
- Layer fingers and whole-cube fingers don't mix: while a layer finger is down, new fingers off the cube are ignored; while the cube is being turned, new fingers join that rotation wherever they land.
- When let go, the whole cube keeps its momentum and settles into the nearest of the 24 square-on orientations, so the front, top and right faces always face the user. Touching the cube stops it where it is.

## App target (`Rubikx/`)

- **`CubeModel`** (`@Observable`): the source of truth. It holds the `CubeState`, the undo history and the solved flags. The view commits finished turns to it, and it reaches the view only through the `CubeCommands` protocol (scramble, undo, reset).
- **`CubeARView`**: `ARView(cameraMode: .nonAR)` wrapped for SwiftUI by `CubeView`. It uses `ARView` rather than `RealityView` for raw per-finger `touchesBegan/Moved/Ended`. It sets up the camera (distance computed so the square-on cube fills the screen width), the light and the per-frame `SceneEvents.Update` tick, and it hit-tests touches with `ray(through:)` to build a `FaceDrag`.
- **`CubeScene`**: the entities. An anchor holds `cubeRoot` (the whole-cube orientation), which holds 26 cubie entities (body plus stickers). During a turn, a layer's cubies are reparented under a per-layer pivot that is rotated. `endTurn` and `sync` rebuild transforms from `CubeState`, so floating-point error never builds up.
- **`TouchController`**: one state machine per `UITouch`. A finger starts *pressing*: off the cube it already rotates the whole cube, on the cube a move becomes a sticker push, and if every finger stays still, the per-frame `update(now:)` turns them into a grip. Layer fingers go undecided (pushing or gripping) → turning, or pending when their axis is blocked. Others are whole-cube or ignored.
- **`TurnEngine`**: the angles of the off-grid layers, the release springs, the same-axis rule, queued moves (scramble and undo, which aren't recorded in history), and commits to the model.
- **`WholeCubeRotator`**: trackball and two-finger twist on `cubeRoot`, then an `OrientationSpring` settle on release.
- **`Haptics`**: Core Haptics transients, falling back to impact generators: a firm squeeze when a long-press grips, a light tap when a finger catches a layer, soft ticks as a held layer passes each quarter turn, a crisp click the moment a released layer reaches its quarter turn (not when the spring finally settles), a softer thud when the whole cube settles, and a success notification on solve.
